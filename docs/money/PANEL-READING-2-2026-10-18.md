# The panel's second reading of 18 October 2026: the stage-one join, the four specifications, the light sync and the ordering page

One session, the five roles in turn (the review lead chair, the security review, the security review and B, the design review), read from about 23:0x UK on 18 October 2026. The faults are numbered from F-769 (the register's last number after the first reading was F-768). No em dash appears on this page. Everything the panel ran, it ran on lab box B (the Go suites on a fresh clone of the join at 0f260033f, the wallet crate's tests, the pool benchmarks) or read on lab box A (the lab's result file, the library's bytes); nothing ran on the Mac beyond git.

**The verdict on the first line of the ADR: "Money remains research" stands, and the join is the first measured reading of the whole.** What moves it, in one sentence: a two-in two-out proof measured at 128 conjectured bits (a Miden release or a pinned patch with the cubic extension, today's ceiling being 108), the spend verified on an enrolled N100-class node inside the 15 ms and 250 ms rows, and the pruned-sync path built and measured; the hash's cryptanalysis stays the named assumption.

## 1. lead/money-stage1-join 0f260033f (the proof of concept)

**Ruling: PASS WITH RE-CUTS as a proof of concept (F-769 to F-776; the wording re-cuts applied by the review in one commit on the branch; the code faults listed, not fixed). The pool lands on main under its gate at zero through refs/gate/lead/money-stage1-join.**

The questions put to the review, answered from the code paths and not from the page:

- **Are the live chains' rules byte-identical with the gate at zero?** Yes. The one new call in Finalize (consensus.go, settlePoolTxs after settleSponsoredTxs) returns before any read or write unless poolOn(height) holds, and poolOn is `from > 0 && height >= from` with `from` set only by SetPoolFrom, which the backend calls only when params.IgneumPoolFromForChainID(id) is non-zero (eth/ethconfig/config.go); the table IgneumChainPoolFrom holds one entry, 7402: 1, and 7401's entry is gone. The verifier is installed only on the same condition (eth/backend.go). The other node-side changes are an RPC namespace (api_pool.go), engine fields, the research-range constant's end (7399 to 7499, which changes IsIgneumResearchChainID for 7400 to 7499 only, where no chain of record lives; 7322 and 7358 read the same before and after) and the pool package itself, which nothing reaches below the gate. The test TestPoolGateOffByDefault asserts the state root unchanged at gate zero and above the block for a block carrying a shield; the finalize-writes check (tools/ci/checks.d/35-finalize-writes) matches the tree at 26 sites with the commit's Fork-Gate line, run by the review on lab box B.
- **Is the unsafe double unreachable on a live chain id?** Yes, by the landing check: whatever verifier is installed, nothing consults it on a chain whose gate is zero. The flag's own guard (--dev plus a research-range id) is a second belt whose "research range" word includes the live ids 7322 and 7358 (F-771); the guard of substance is the gate and --dev's own genesis.
- **The value rule.** 128 bits of wei as four 32-bit limbs, each limb u32assertw'd in both statements (inputs, outputs, v_pub and the fee), the balance V1 + V2 = VO1 + VO2 + FEE + VPUB by u32overflowing_add3 limb by limb with the carries compared at the top (spend.masm, proc balance), which is exact integer equality over 128 bits on both sides; the node refuses a value past 128 bits before the verifier is reached (maxValueBits) and ValueWord encodes limb 0 as the least significant, the same in Go and Rust by the vectors. Sound against overflow and against the field.
- **One hash across Go, Rust and MASM.** The Go permutation's known answer, the Go TestSharedVectors and the wallet's shared-vectors test pass on lab box B (the panel ran them: not skipped); the prover's test re-derives the file with miden-crypto, and the lab's 101 spends and 104 shields proven by the MASM and verified by the node prove the MASM's H equals the host's, since a differing nullifier or commitment would have failed the statement hash.
- **The verifier binding.** A C-ABI staticlib over miden-verifier and miden-assembly (never the prover), the claim built from the pinned program hash, the statement hash as the stack input and as the first word of the outputs; the library's two program hashes checked at start against pinned.go (a library built from other assembly is refused at New); BLAKE3 required as the commitment hash; the conjectured level read from the proof's own parameters and refused below 108; a Rust panic caught at the boundary and returned as a refusal. The trust is in the pinned crates (Cargo.lock committed, every miden crate "=0.36.1"), the committed patch and the toolchain; the page did not carry the library's bytes (F-770): the review read them on lab box A, libmoney_verifier.a sha256 2fb2ab081b4c467a..., rustc 1.99.0, and the page now does. An operator reproduces the bytes by prepare-patched.sh and build-node-verifier.sh on the same toolchain; the two-builder byte-identical compare is the release team's item, as the page says.
- **The refusal rows and the reconciliation.** Read in the sealer's log on lab box A (the seven refusal reasons, each twice as the sealer runs Finalize twice) and the driver's result.json (turnstile 142,705,664,062,499,903,765 wei, 306 notes, 104 shields, 101 transfers, reconciled true, 175 roots): the figures on the page are the lab's.
- **The 108-bit ceiling against the ADR's 128.** Honestly stated, with the term that binds (the lookup-challenge term of the quadratic extension) and the patch recorded; the estimate for the cubic extension is marked as one. "Money remains research" is the right first line.
- **Proof pruning as a rule.** The rule is sound as stated: every later spend is validated from the pool's consensus state (the nullifier set, the recorded roots, the tree's frontier and root) and the new proof, never from an old proof, so a node that dropped every proof after import validates every later spend; what an archive keeps is the bodies with the proofs; the retained set is served by igneum_poolBlock. The drop and the pruned sync are not built and the page says so (ADR row 5 FAIL stands).
- **The seed birthday.** Landed as the page says; one honesty item listed (F-776).
- **The figures' provenance.** The lab's result file and logs on lab box A, the bench's medians named; the page now carries the library's sha and the compiler (F-770).
- **The suites.** The panel's own run on lab box B (go test ./... with a 25-minute timeout): the pool package and params green, cmd/geth's three failures (TestGethFailureToLaunch, TestCustomBackend, TestCustomGenesis) present and identical to clean main as the page reports; the wallet crate 16 unit and 3 integration tests green; the count of record stays the page's 2,345 pass and 9 fail, every failure in a package the cut does not touch.

### The faults

- **F-769 (chair, process; not a fault in the cut).** The branch reached the box's git as a bundle relayed through the Mac because lab box A's mirror key cannot push. The cure: a push key for the lab box (or a path from lab box A to the lab directory with the seat's identity), issued by the release team, so that no cut is ever relayed through the Mac again.
- **F-770 (the security review; wording, applied).** Section 6's release-form sentence carried the lab binary's sha and not the library's bytes or the compiler that made them. Re-cut: the sentence now carries libmoney_verifier.a's sha256 2fb2ab081b4c467aefb75b832390e0c4d7ab5a6951e6db69a0938904a76d81c8 and rustc 1.99.0 (b940084d7 2026-09-28), read on lab box A, and names the missing rust-toolchain file. Code item: a rust-toolchain.toml pinning 1.99.0 in tools/money/stage1-prover.
- **F-771 (red team; code, listed).** eth/backend.go's guard for --dev.pool.unsafe-verifier refuses the flag outside --dev on a research-range id, and the comment says "never on a chain of record"; the research range (7311 to 7499) contains 7322 and 7358. The gate at zero makes the double unreachable on those ids whatever the flag; the guard should still refuse any id that carries an entry in IgneumChainRuleForks (a chain of record by construction), and the comment should name the gate as the guard of substance.
- **F-772 (chair; wording, applied on the ADR, which the join branch carries from main).** ADR section 4.3 item 2 read "v a 64-bit wei-scaled amount" and "cm = H(v, pk, r)"; item 4 read "tx_hash = B(all other transaction bytes)" and "that tx_hash is the public input it was proven against". The join built 128-bit values as four limbs, the nested merge form, and a statement hash over the domain word and the public inputs with no tx_hash and the ciphertexts unbound. Re-cut: both items now state the built form and name the ciphertext binding as the vault cut's one-word change; the status line names this reading.
- **F-773 (chair, the design review; wording, applied).** The three superseded pages land on main under the join with no word of what overturned them: cut one's "37 queries make 128" (overturned by the lookup-challenge ceiling), cut two's BLAKE3, one-to-four nullifiers, proofless shield and chain 7401, cut three's 64-bit value, stand-in hash and 1,317-byte output. Re-cut: one SUPERSEDED paragraph at the head of each, naming the join as the record and the sentences overturned.
- **F-774 (the security review; design, listed).** record.go's MaxCiphertext is 2,048 bytes; the join's output ciphertext is 1,293 and the light-sync page's clue 768, together 2,061. The clue gate (IgneumMoneyClueFrom) carries the clue in a field of its own or raises the bound; said on the light-sync page's status line.
- **F-775 (red team; code, listed).** Value can sit above the turnstile with no path out and no theft: a contract's internal call that sends value to the pool address (no transaction to the address, so Finalize never reads it), or a spend naming the pool address as its public output (the value lands back in the pool's balance above the turnstile). Neither moves money to anyone; both lose it. The signerless type's rules (F-761) must refuse the pool address as a public output and define what the pool does with value that arrives by any path but a shield.
- **F-776 (the design review, the wallet's honesty rules; code, listed).** `restore --birthday H` with an H later than the seed's true creation height hides every note before H, and the tool says only "a restore scans from it". The ADR's section 8 asks for the words: the restore should say that a birthday later than the true one hides the notes before it and that a doubtful birthday is given as zero.

## 5. lead/money-specs e7d097bad (the vault, the payout privacy, the network privacy, the test plan)

**Ruling: PASS WITH RE-CUTS (F-777 to F-786, applied by the review in one commit on the branch); landed on main through refs/gate/lead/money-specs as documents of record.**

The vault's authority separation, read hardest: it holds as a specification. The only statements that write a new policy_hash are S_rec_announce (t guardian signatures in the witness) and S_rec_complete (rec_hash set and R passed); S_withdraw and S_merge copy policy_hash from head_in to head_out as a circuit constraint; the delays D_b and D_s are copied from the policy inside S_withdraw and fixed in the pending note's commitment, so no statement the everyday key can prove shortens one; fees come from ordinary notes by the conservation check over them alone; the statement id is public, so a node refuses a policy change from the statement id and the proof alone. The stolen-key figure's derivation had two holes (F-777, F-778) and the ledger leaked one link the page did not state (F-779). The shielded coinbase's supply reconciliation: the mint record is recomputed by every node from public data, the ledger's identity 3 splits credited from minted, and the turnstile counts the mint; the page forgot the pool address's balance, which the pool form of record keeps equal to the turnstile (F-782).

- **F-777 (chair, red team; applied on VAULT-SPEC sections 1 and 9 and TEST-PLAN V-19).** The bound "W + L times ceil(max(0, R minus D) over P)" undercounts: the thief's requests can use every period index whose blocks fall in the window from the theft to R minus D later, plus the 64-block declaration margin, which is up to floor((R minus D + 64) over P) + 2 indices, not ceil((R minus D) over P). With the defaults (D and P one day, R three days) the common case is W + 3 L, the worst alignment W + 4 L, not W + 2 L. Re-cut to the exact count, the common case and the worst case; V-19 now runs both alignments (W + 2 L and W + 3 L at the test defaults).
- **F-778 (the security review; applied on VAULT-SPEC sections 3.5 and 8 and TEST-PLAN A-06 and V-17).** "The node accepts a revoked_root from the last 128 canonical blocks" let a pending note of a revoked policy complete for 128 blocks after S_rec_complete landed, by a proof of non-membership against a root older than the revocation; and "the same window as the anchor" was wrong (the pool's anchor window is 64 recorded roots). Re-cut: the node accepts only the revoked set's root at the parent of the including block, a stale proof is re-proven (recoveries are rare), the revocation binds from the block after S_rec_complete; A-06's window is 64 recorded roots.
- **F-779 (the security review, red team; applied on VAULT-SPEC sections 3.3 and 10).** The position tag ptag = H("ptag", cm_pending, position) is computable by anyone from the public commitment and its position, so every completion and cancellation was linked on the ledger to the request that made the pending note, while section 6 said only "which vault" is hidden. Re-cut: ptag = H("ptag", cm_pending, position, r) with r the pending note's randomness, which both consumers read from the ciphertext and nobody else holds; section 10 states the residual (the statement-id count per block).
- **F-780 (chair; applied on VAULT-SPEC's status line and sections 3.2).** "Amounts are in wei, 64 bits" and the head's "v, 64 bits" are the join's 128 bits as four limbs; and "S_transfer, whose circuit checks cm = H("note", v, pk, r)" is not the built statement: money-spend-v1 checks cm = H(H(v, pk), r) with no domain word, so the head's separation rests on second-preimage resistance until the vault cut adds the word as money-spend-v2. Re-cut to say so.
- **F-781 (the design review; applied).** "the brief's rolling commitment" (process words) is now "the ADR's section 2.2 rolling commitment".
- **F-782 (chair; applied on PAYOUT-PRIVACY-SPEC sections 4.2 and 5).** The mint advanced the turnstile and not the pool address's balance, and "the new anchor checked against the header's anchor field" named a field that does not exist (the root lives in the pool's state under the state root). Re-cut: the mint credits the pool address with v_K in place of the 0x credit, and the root is recorded in the pool's state.
- **F-783 (chair; applied on PAYOUT-PRIVACY-SPEC section 7).** "1 to 5 microseconds per H on one N100-class core" was an estimate below the measured Go merge: the panel's benchmark on lab box B reads the shield admission at 225 microseconds under Poseidon2 against 172 under BLAKE3 over 32 merges, about 2 microseconds a merge on an EPYC core, 4 to 8 on the N100 class, so 33,000 merges are 130 to 260 ms and cross the row's 165 ms. Re-cut: the batched insertion (about n + 64 merges for n consecutive leaves) is the rule, at about 1,100 merges, 4 to 9 ms, both figures replaced by the stage 7 measurement.
- **F-784 (chair; applied on NETWORK-PRIVACY-SPEC sections 3.1 and 3.3).** Section 3.3 named fuzzy message detection and oblivious message retrieval as "the path if the rate grows a hundredfold" while the light-sync page (its own branch) chose a lattice clue and rejected the curve form; re-cut to point at that page. Section 3.1's "decapsulates 20,000 outputs in ESTIMATE under 2 seconds (ADR's 0.1 ms)" is re-cut to the measured 32 microseconds a ciphertext on a server core and a phone at 3 to 10 times: 2 to 6.4 seconds.
- **F-785 (the design review; applied on NETWORK-PRIVACY-SPEC sections 4 and 5).** The served sentence "the public node keeps no log of who asked what" was written as a sentence the site says, ahead of its row J-07; re-cut to "may say once row J-07 has passed and not before". "The reliability lane's $hname lesson" (process words) is now "the console's hostname rule of record".
- **F-786 (chair; applied on TEST-PLAN A-01 and A-02).** The rows attacked 2^64 minus 1 and 2^64, the ADR's old 64-bit value; re-cut to the limb form (2^128 minus 1, and one limb of 2^32, which u32assertw refuses).

## 6. lead/money-light-sync dbe736851 (the light-sync specification)

**Ruling: PASS WITH RE-CUTS (F-787, F-788, applied in one commit on the branch); landed on main through refs/gate/lead/money-light-sync as a document of record.**

The lattice clue's leak figures re-compute (pN at one in sixteen: 125, 3,750 and 12,500 a day at the three rates; the candidate download 4.94 MB a day at 30,000 transfers; the server's 27-microsecond bound from cut 3's decapsulation); the fuzziness argument of section 2.3 is sound as a reading (a wrong K-PKE secret decrypts to a pseudorandom ring element under module learning-with-errors, so four fixed bits pass at 2^-4 up to a term of order t over q, and the KEM's re-encryption check, which would make detection exact, is absent by construction); the 768-byte cost on every output from the landing check is stated as the page's finding, paid by every node that keeps clues; the first-release rule (no light mode, address v2 with ek_det from the first release, the clue at one gated height for everyone) is the right order and commits the address to 2,027 bytes before the review's decision on the clue, which the page says. The sizes are FIPS 203's (ML-KEM-512: ek 800, s 768, ciphertext 768; the decryption failure 2^-139).

- **F-787 (chair; applied on the status line).** The page's output figure is cut 3's 1,317 bytes; the join made it 1,325, a difference under one percent that moves no figure's first two digits except the threshold (about 9,400 transfers a day at 1,325); and the clue beside the join's ciphertext is 2,061 bytes against MaxCiphertext 2,048 (F-774). Both now on the status line.
- **F-788 (the security review; applied on section 2.3 item 3).** The anonymity result was cited approximately with the review asked to name it. Named: the Kyber IND-CPA proof (ePrint 2017/634, the two-step hybrid that makes the ciphertext uniform under module learning-with-errors even to a holder of every public key), which is key privacy for the plain K-PKE clue directly; the two KEM anonymity papers cover the Fujisaki-Okamoto form and are not needed. The engineering session confirms the citation against the source.
